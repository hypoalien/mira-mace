# Mira Mace DME coordinator

A demo of a patient advocate coordinating a **standard manual wheelchair (K0001)** request. One agent works with the PCP, the patient, and Medicare-enrolled suppliers while a case page shows what is known, what has been requested, and what is still waiting for a response.

This is a simulation: no calls, orders, claims, or deliveries are sent to real systems. The external parties' answers are entered by you or generated by the demo's mock-response flow.

## Run with Docker

You need Docker Desktop and an OpenAI API key. From a clone of this repository:

```bash
git clone <repository-url>
cd mira-mace-takehome
cp .env.example .env
```

Edit `.env` and set `OPENAI_API_KEY` to your key, then run:

```bash
docker compose up
```

- App: [http://localhost:3000](http://localhost:3000)
- Temporal UI: [http://localhost:8233](http://localhost:8233)

Press Ctrl+C to stop the foreground process, then run `docker compose down`. Case records and Temporal history remain in Docker volumes. Use `docker compose up --build` after changing code.

## Try a case

1. On the case list, click **Create case from intake**. The new case starts with the patient, insurance, PCP, and equipment from `data/intake.json`.
2. Open it and click **Start DME agent**. The agent reviews the current case and can queue supplier, PCP, and patient outreach in the same round. The chat shows its streamed updates and tool activity.
3. Respond to pending requests. With **Auto mock** off, choose **Positively**, **Negatively**, or **No response** in the chat. Use **External responses** for the full questions and editable answers. With Auto mock on, configure the outcome of each attempt for each supplier, the PCP, the patient, and later delivery steps; the demo records the responses automatically.
4. Follow the case through supplier selection, document review, offer and cost details, patient agreement, booking, delivery proof, and patient confirmation. The right panel shows the evidence and current status. The **Patient** chat tab can receive updates and patient replies.
5. To explore delays, choose **No response**. The case schedules a next-day follow-up; **Run follow-up now** advances demo time. After three unanswered attempts, a care advocate task appears. **Generate resolution** drafts answers to the blocked call, and **Resolve task** records them so coordination can continue.

**Reset case** starts that case again from the intake fixture while keeping its case ID and URL. It clears its stored messages and coordination history.

## How it works

| Part | Responsibility |
| --- | --- |
| Next.js (`src/app/`) | Case list, case workspace, patient chat, external-response page, and API routes. |
| Agent (`src/ai/`) | Reads the latest case context, chooses eligible actions, writes questions and messages, and streams updates through the Vercel AI SDK with Temporal's adapter. |
| Temporal (`src/temporal/`) | Runs one durable workflow per case. It waits for mock responses, chat messages, and scheduled follow-ups, then resumes the agent. |
| Case logic (`src/lib/dme/`) | Records mock answers and enforces prerequisites for supplier selection, patient agreement, booking, and delivery verification. |
| JSON store (`data/cases/`) | Saves each case's messages, calls, documents, status, and care advocate tasks. The app and worker share this directory through a Docker volume. No database is required. |

The model decides what to ask and which available tool to use. The case logic checks the resulting facts before advancing. For example, a booking requires patient agreement to a specific offered delivery window, and completion requires both supplier delivery evidence and the patient's confirmation. The agent does not treat an unanswered request as a completed call.

`data/suppliers.json` is the supplier directory. `public/demo-documents/` contains fictional PCP PDFs used for mock document responses; their text is extracted and supplied to the agent as case context. These files are demo fixtures, not documents received from a real practice.
